Reference: Drive file 1qIq8QaZd89N7WZac7vXHvuB5XYZ6AZnz, actual PDF pp1,3–4 visually inspected.

This is the active ARC_N presentation override. It overrides conflicting ARC_N color/typography/reference declarations in the shared PDF master and legacy N HTML. ARC_CORE and ARC_FINAL retain their own rules. The override changes presentation, not content or answer keys.

- A4 portrait; white paper, black text and rules; only neutral grays in table headers.
- Outer horizontal margins 12.7mm, gutter about 7mm; thin central divider.
- Fixed two-column problem flow. Read left top-to-bottom, then right top-to-bottom.
- Target four moderately sized questions per page; use two/three if full material requires more room. Never force four or hide overflow.
- Stem 9.7–10.2pt, regular body/choices 9.5–10pt; leading about 1.5. Table/graph labels at least 8pt unless individually reviewed.
- Plain question numbers; no student-facing difficulty, guessed exam attribution, point values, hints or solved-result labels.
- Render tables/graphs/particle models as sharp vectors. Graph axes, units and legends must be complete; nonlinear models must not be replaced by straight segments.
- Use real chemical superscript signs and subscript numerals; font coverage check precedes export.
- Do not redraw a canonical logo. Text `ARC N°` is a running series label, not a new logo asset. A grayscale cover may use the existing approved mark only when sourced and verified.
- Physical sequence: cover; one completely blank verso; problem pages; one completely blank separator; compact number+answer key.
- Keep a whole stem, its material and choices together. Move the entire question to the next slot/page when necessary.
- Validate actual PDF text count/numbering, page bounds, all blank pages, embedded font glyph coverage and all-page image renders. Color data sources may be inspected privately; never copy them into the output as figures.
