# ARC_VIEW_EVIDENCE_POLICY_V1.0 — 무힌트 `<보기>` 원칙
VERSION: 1.0
DATE: 2026-11-19
STATUS: ACTIVE
SCOPE: 모든 과목. 자동 검사는 규범 문항(국어 문법·맞춤법·띄어쓰기·표준 발음 등)에 적용
EXECUTABLE: `tooling/content_qa/content_qa_gate.py` → `lint_bundle_text` (`VIEW_SOLUTION_LABEL`, `VIEW_SOLUTION_FORMULA`)
ORIGIN: 2026-11 한글 맞춤법 실전 세트 비교(3-DAY PACK vs 내신형 V2) 사용자 검증. `<보기>`에 정답 판별 공식이 들어가 문항이 공식 대입 문제가 됨.

## 1. 원칙
`<보기>`는 학생이 **판단에 쓸 사실 자료**를 준다. 판단 결과를 미리 알려 주는 **풀이 공식**은 주지 않는다.
학생이 해야 할 일(조항을 사례에 적용하기)을 `<보기>`가 대신하면 그 문항은 변별력이 없다.

## 2. 허용 자료 (화이트리스트)
| 표지 | 내용 | 예 |
|---|---|---|
| 조항 원문 | 「한글 맞춤법」·「표준어 규정」·「표준 발음법」 등의 조항을 **원문 그대로** (제n항, [붙임], [다만]) | 제40항 [붙임 2] 어간의 끝음절 '하'가 아주 줄 적에는 준 대로 적는다. |
| [발음 자료] | 표준 발음 표기 | 깨끗하지 않다[깨끄타지 안타] |
| [사전 뜻풀이] | 사전의 품사·뜻풀이 | 만: 「의존 명사」 앞말이 가리키는 동안이나 거리. |
| [짜임 자료] | 형태소 분석·단어 구조 | 생각-하-건대 |
| [예문]·[학생의 글]·[탐구 대화] | 판단 대상 문장 (㉠~㉤ 표시) | |

## 3. 금지 자료
- `[해설 자료]`, `[풀이]`, `[판별 기준]`, `[힌트]`, `[정리]`, `[요령]`, `[공식]` 같은 표지 자체
- 조항 원문에 없는 **파생 판별 규칙**: "'하' 앞 받침이 [ㄱ, ㄷ, ㅂ]이면 '하'가 탈락한다", "받침이 ㄹ이면 붙여 쓴다" 등
- 조항 원문을 바꿔 쓰면서 조건·결과를 단순화한 문장 (조건문 + 표기 결과: ~이면/~일 때/~인 경우 … 탈락/줄어/붙여 쓴다/띄어 쓴다/~로 적는다)

## 4. 분류형 원형(A3)과 조항 요약
`<보기 1>` 조건 Ⓐ/Ⓑ/Ⓒ로 분류하게 하는 원형(`quality/korean/ARC_KOR_GRAMMAR_ARCHETYPES_V1.1.yaml` A3)은 허용한다. 단,
- 각 조건은 조항 원문이거나 원문과 뜻이 같은 문장이어야 한다.
- 문항에 `view_clause_refs: [제41항, 제42항]`처럼 근거 조항을 적는다. 적으면 정적 검사는 WARN으로 낮아지고, 검수자가 원문 일치 여부를 확인한다.
- 근거 조항을 적지 않은 조건문은 FAIL이다.

## 5. 문학·비문학 `<보기>`
문학의 외적 준거, 비문학의 사례·관점 자료는 해석 맥락이므로 이 정책의 자동 검사 대상이 아니다.
다만 `<보기>`가 정답 선지의 문장을 거의 그대로 담아 답을 노출하면 `quality/ARC_ITEM_QUALITY_RUBRIC_V1.6.md` §1A로 FAIL이다.

## 6. 검사 대상 판정
번들에서 다음 중 하나면 규범 문항으로 본다: 번들 `v6:` 블록, 문항 `v6_area`, `domain: GRAMMAR/NORM`, 선지 판단 `axis`가 orthography/spacing/grammar/pronunciation/morphology/phonology/norm 등, `normative: true`.
