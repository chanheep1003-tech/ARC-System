## 0. 한 줄 정의
ARC CORE는 **상세 개념서**다. 해당 과목을 처음 보는 학생이 앞에서부터 따라가면 개념이 서는 책이며,
줄글 나열이 아니라 **번호 소단락 · 표 · 흐름도 · 중요/심화 상자 · 예제 · 확인 문제**로 짠다.
학교 시험 대비는 별도 장 + 개념별 상자의 두 겹으로 붙인다.

## 2. 책의 뼈대 (순서 고정)
1. 표지
2. 이 책을 읽는 방법 — 구성요소(중요/심화/참고/확인/시험 포인트)와 기호(★ † ◇)의 뜻, 자료 우선순위, 출제 단정 안 함 문구
3. 차례 — 장/개념/쪽수 (쪽수는 2-pass로 채운다)
4. 시작하기 전에 — 입문 개념(000): 이 단원이 왜 어려운지, 용어 최소 사전, 읽는 순서
5. 본문 장(Ⅱ…Ⅴ …) — 장 시작 쪽(opener) → 개념들
6. 시험 대비 장 (§7-2)
7. 모의 문제 · 정답과 해설
8. 부록 — 색인(용어/개념)

분량 기준: 개념 1개 = 1~3쪽, 책 전체 40쪽 이상(단원 크기에 맞춰 조정). 쪽 수를 맞추려고 같은 내용을 반복하지 않는다.
짧은 꼬리 쪽(점유 35% 미만)이 생기면 **예제 · 보충 소단락**을 넣어 메운다 — 장식으로 메우지 않는다.

| 7 | 확인 문제 3~4개 + 정답(작게) | 필수 | 개념 직후 자기 점검 |

## 4. 쓰기 규칙
### 4-1. 소단락
- **한 소단락 = 한 가지 생각.** 번호 + 소제목 + 본문 + (표 | 흐름 | 도식).
- 연속 줄글은 **3~4문장 이내**. 그 이상이 되면 표·흐름·대조로 바꾼다.
- 용어는 **처음 나올 때 풀이**한다(옆 칸 `.side` 또는 본문 괄호). 풀이 없이 용어를 던지지 않는다.
- 순서: 정의 → 보기 → 반례/경계. 학생이 ‘왜’를 묻는 자리에서 이유를 한 줄 붙인다.
- 소단락은 **쪽 중간에서 끊기지 않는다**(`break-inside:avoid`). 길면 둘로 나눈다.
- 옆 칸(`.side`)은 보조다. 옆 칸을 읽지 않아도 본문 흐름이 이어져야 한다.
### 4-2. 중요 포인트
- 시험의 판단 기준이 되는 것. **외울 문장이 아니라 ‘왜 그런지’까지** 적는다.
- 개념당 1~2개. 상자 머리띠(검정 반전)가 상자 안에 있어야 한다(쪽 분할 시 태그만 떨어지는 것 방지).
### 4-3. 심화 포인트
- 교과서·학교 자료 밖이어도 개념 이해에 실제로 도움이 되는 것. 점선 상자, 회색 머리띠.
- 학교 자료 밖 보충은 **†** 로 표시한다. “처음 읽을 때는 건너뛰어도 된다”가 성립해야 한다.
### 4-4. 기호 (읽는 방법 쪽에 설명 필수)
- **★** 학교 자료가 직접 강조한 곳 · **†** 학교 자료 밖 보충 · **◇** 자료 간 불일치·원본 확인 필요
- ◇는 학생 쪽에서는 해당 위치의 기호와 안내 문구까지만 보이고, **확인 필요 목록 자체는 내부 문서**다(§8).
### 4-5. 표·도식
- 표는 비교축이 있을 때만(2축 이상). 같은 사실을 표와 문단으로 두 번 쓰지 않는다.
- 도식은 새로운 관계·순서·비교를 줄 때만. SVG/CSS로 그린다(이미지 캡처 금지, 글자는 텍스트로 유지).
- 흑백에서 구분이 유지돼야 한다(§5).

## 5. 흑백 규칙 (HARD)
- 색은 **회색조(r=g=b)만** 쓴다. 강조는 굵기 · 반전(검정 바탕 흰 글씨) · 이중선 · 점선 · 음영 회색으로 만든다.
- 소스에서 `#rrggbb`가 gray가 아니면 빌드가 FAIL한다. 래스터 검사(채널 차이 ≤ 8)도 통과해야 한다.
- 장식 아이콘·이모지·마케팅 카피 금지. ‘AI 카드’ 인상을 주는 둥근 모서리·그림자·알약 배지 금지.

## 6. 예제와 확인 문제
- 학교 기출 문장을 복제하지 않는다. 기출은 **유형·사고 형태**만 가져오고 문장은 새로 만든다.
- 예제는 ‘주어진 자료 → 판단 순서 → 결론’ 3단으로 보여 준다. 정답만 적지 않는다.
- 확인 문제의 정답은 문제 바로 밑에 작게 둔다(스스로 점검용). 해설은 한 줄.
- 모의 문제는 실제 시험 형식(선택형 + 서답형, 〈보기〉 조합형)을 따르되 **기출 복제 아님**을 근거 칸에 밝힌다.
- 과목 정답 규칙(KOR 단일 정답, 근거 추적 등)은 해당 SUBJECT_MASTER가 우선한다.

## 7. 학교 시험 대비 (SCHOOL-EXAM LAYER)
### 7-1. 개념별 시험 포인트 상자 (3행 표)
| 행 | 내용 |
|---|---|
| 근거 | 학교 보충자료 ★ · 교과서 수록 · 전년도 기출 유형 중 **실제로 있는 것만**. 근거 밀도를 ★ 개수로 표시 가능 |
| 나오는 모양 | 이 개념이 문제가 될 때의 형태(어절 판정, 〈보기〉 조합, 서술형 틀 채우기 …) |
| 조심할 곳 | 실제 혼동 지점(학교 자료의 대비쌍, 기출 오답 유형) |
- “반드시 나온다 / 100% / 무조건” 금지. 근거가 없으면 상자를 만들지 않는다.
- 다른 학교 기출은 **난도 가늠에만** 쓴다. 해당 학교의 출제를 짐작하는 근거로 쓰지 않는다.
### 7-2. 시험 대비 장 (고정 구성)
A. 기출 영역 분포표(문항 수·배점은 원문 배점표로 계산, 임의 반올림 금지)
B. 근거 밀도 순위(수식 공개: 기출 문항 수 · 학교 ★ · 교과서)
C. 유형 지도(유형 × 근거 × 개념 × 사고 과정 × 대표 함정)
D. 서답형 훈련(문장 틀 · 조건 · 오개념 감점 포인트)
E. ★ 총정리
F. 시험 직전 점검표
G. 모의 문제 + 정답·해설
- 학교 시험 문장을 복제하지 않고, 인접 범위(예: 맞춤법)는 “이 책 범위 밖” 한 줄로만 표시한다.

## 8. 학생 PDF에 넣지 않는 것 (INTERNAL / DO NOT PRINT)
- CORE_META, CORE_ARCHITECTURE_SUMMARY, CORE_INTEGRITY_INDEX, CORE_LINK_INDEX(개념 ID ↔ ARC N° 연결), QC_STATUS,
  ◇ 확인 필요 목록, 제작·검수 메모, Drive/SOURCE_ID/BATCH_ID.
- 개념 번호(박스)와 소형 **단원 코드**(예: ARC-KOR-MID-001)는 학생 쪽 탐색용으로 허용한다. N° 문항과의 연결표는 내부 전용이다.
- 위반 시 `STUDENT_METADATA_LEAK` → FAIL.

## 9. 제작 파이프라인 (Generator → Typesetter → Publisher)
1. Generator: handoff Markdown(원고)만 만든다. 레이아웃 지시 금지. 원고는 §3의 구성요소를 **의미 마커**로 표시한다
   (예: `::: important`, `::: advanced`, `::: check`, `::: exam`, 소단락 `### n 제목`).
2. Typesetter: `core_profile = BOOK`이면 `templates/core/ARC_CORE_BOOK_master_v0.4.html` + `templates/core/book/ARC_CORE_BOOK_style_v0.4.css`로 조판한다.
   `tooling/core_book/build_book.py`가 gray 검사 → 렌더 → 2-pass 차례 쪽수 → 래스터 gray 검사 → `pdf_preflight --core-profile BOOK`를 수행한다.
3. Publisher: Drive 저장. PDF 바이너리 업로드는 사용자 승인 경로(FILE_REFERENCE_FIRST)를 따른다.
